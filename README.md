# Libre Ledger

Личный учёт сенсоров: партии со сроками, закупки, продажи, бесплатные передачи и списания. React + TypeScript + Vite, GitHub Pages, Firebase Authentication / Firestore. Пустой учёт не содержит примеров или готовых моделей.

## Повседневная работа

- **Главная**: прибыль, продано в рублях и штуках, закуплено с доставкой в рублях и штуках, текущий склад в рублях и штуках. Бесплатные передачи включены в количество и отмечены отдельно.
- **График продаж**: линия, периоды 1/3/6 календарных месяцев по сегодняшний день, рубли или штуки. За текущий месяц — по дням, более длинные периоды — по неделям. Выбор точки мышью, касанием и ползунком с клавиатуры. Ссылка открывает операции выбранного периода.
- **Склад → Модели**: название, цвет и необязательная цена продажи по умолчанию. Нулевая цена допустима.
- **Закупка**: количество, цена, доставка, необязательный месяц/год срока. Несколько сроков добавляются отдельными строками; общая доставка распределяется один раз пропорционально количествам с точностью до копейки.
- **Склад → Партии**: остатки сгруппированы по модели и сроку, с раскрытием закупок. Доступны фильтры срока, просроченного товара и партий без срока, продажа и списание из конкретной партии.
- **Продажа**: фиксируется количество из каждой выбранной партии. Автопредложение по ближайшему сроку, ранней закупке или ручной выбор. Просроченные не добавляются автоматически. Бесплатная передача уменьшает остаток и учитывает стоимость товара в прибыли.
- **Списание**: количество из выбранных партий и причина, без фиктивной продажи. Стоимость выбывшего товара учитывается в прибыли.
- **Операции**: исправление, отмена, восстановление и удаление. Проверяется вся затронутая история, включая более поздние операции. Отмена возвращает товар в исходные партии.

Срок `03.2027` означает до конца марта 2027. Он не удаляет товар автоматически. Партия без срока остаётся доступной с явной отметкой. Даты закупок/продаж не могут быть в будущем; для срока годности будущий месяц разрешён.

## Расчёты и старые записи

Новое пустое пространство использует стоимость конкретных партий с доставкой. Расчёт этого метода ведётся в целых копейках; неделимая доставка распределяется детерминированно, и после полного выбытия партии не остаётся денежного хвоста. Публичные поля цены в JSON остаются в рублях для совместимости.

Существующий учёт при переносе сохраняет среднюю стоимость и прежние финансовые итоги. Старые продажи без выбранных партий не становятся выдуманной точной историей: остатки таких партий помечены как оценочные. Их можно сверить через редактирование продажи. При оценочном остатке проверяйте фактические партии перед подтверждением новых распределений.

**Настройки → Метод расчёта прибыли** позволяет перейти между методами после сверки, предварительного сравнения и подтверждения резервной копии. Изменение пересчитывает историю. Отпечаток операций и версия настроек защищают от подтверждения устаревшего результата после изменений с другого устройства.

## Настройки

Название магазина, начальный раздел, приоритетный показатель, период/единица графика, предупреждение о сроке, малый остаток и предложение партий сохраняются для аккаунта. Размер текста и уменьшение анимаций действуют на текущем устройстве. Цены по умолчанию задаются в моделях. Сброс настроек не удаляет операции.

Доступны текущий статус и время подтверждения синхронизации, повтор отправки, восстановление пароля, экспорт/импорт JSON, скачивание архива до обновления и очистка рабочего учёта. Очистка рабочего учёта сохраняет отдельный архив перед обновлением.

## Хранение и миграция

Изменения сначала сохраняются локально, затем отправляются транзакциями Firestore. Очередь переживает перезагрузку. Конфликты сохраняют локальную копию для восстановления; облачные данные не перезаписываются вслепую. Две продажи последней единицы одной партии не могут обе подтвердиться в облаке. Офлайн-операция до подтверждения сервера имеет статус ожидания.

Гостевой и аккаунтный учёт разделены. Вход не переносит гостевые записи автоматически. Для намеренного переноса используйте копию и восстановление. Кэш и ожидающие действия остаются на устройстве после выхода; используйте доверенный браузер. JSON-копии содержат данные без шифрования.

Формат v3 переносит поддержанный старый документ без очистки. В одной транзакции сохраняется точный оригинал в `users/{uid}/workspace/pre-v3` и обновляется рабочий документ. Архив защищён от изменения и доступен владельцу для скачивания. Старые локальные ключи остаются сохранены. Неизвестная будущая версия блокирует запись; повтор синхронизации не должен затереть такую копию.

**Правила v3 публикуются до нового клиента.** Они поддерживают старый v2 до миграции и запрещают старой вкладке понизить или очистить v3. Старый клиент мог пытаться очищать незнакомые версии; поэтому порядок выпуска обязателен. Откат интерфейса не означает разрешения понизить формат рабочих данных.

## Ограничения и бесплатная инфраструктура

До 100 моделей, 3000 операций и 750 КБ полезных данных; перед записью учитывается также объём метаданных. JSON-файл восстановления — до 3 МБ, после чтения проверяется допустимый размер содержимого. Цена/доставка — до 100 млн ₽, совокупные закупки и продажи — до 1 трлн ₽ каждая. При приближении к пределу сохраняйте резервную копию; данные автоматически не удаляются.

GitHub Pages и Firebase Spark работают в пределах [бесплатных квот](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans). Cloud Functions, платные API и автоматическое подключение биллинга не используются. Доступ разрешён только подтверждённому владельцу `andrewokop@gmail.com`. Это личный учёт: правила ограничивают доступ и формат документа, а не являются отдельным серверным бухгалтерским движком.

## Разработка и проверки

Node.js 22+, для эмулятора Java 21+.

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
npm audit --omit=dev
npx --yes firebase-tools@15.34.1 emulators:exec --only firestore --project demo-libre-audit "npx vitest run tests/firestore.rules.test.ts"
```

Без эмулятора тесты правил явно пропускаются. GitHub Actions выполняет unit-тесты, эмулятор и сборку перед публикацией Pages.

Для браузерных сценариев создайте `output/playwright`, запустите локальный сервер и отдельную сессию Playwright CLI:

```sh
npx --yes --package @playwright/cli playwright-cli -s=ledger-check open http://127.0.0.1:5173/
npx --yes --package @playwright/cli playwright-cli -s=ledger-check run-code --filename tests/management.browser.js
npx --yes --package @playwright/cli playwright-cli -s=ledger-check run-code --filename tests/finance.browser.js
npx --yes --package @playwright/cli playwright-cli -s=ledger-check run-code --filename tests/readability.browser.js
```

Сценарии работают только с локальным сервером и тестовым гостевым учётом. Они меняют его содержимое. Не используйте сессию с рабочей авторизацией. Проверяются партии, сроки, бесплатные передачи, списания, настройки, резервная копия, сверка, график и читаемость 320–1920 px с тремя размерами текста.

Публичная конфигурация существующего Web App — `src/firebaseConfig.ts`, переопределения — `VITE_FIREBASE_*` из `.env.example`. Не добавляйте сервисные ключи или OAuth-токены в клиент. Firebase Web API key публичный; защиту данных обеспечивают авторизация и серверные правила.

## Публикация

Сначала проверка правил в эмуляторе, затем из аккаунта владельца:

```sh
npx --yes firebase-tools@15.34.1 deploy --only firestore:rules --project freestyle-libr
```

После этого push в `main` запускает `.github/workflows/deploy.yml` для GitHub Pages. Рабочее пространство переносится при открытии нового клиента владельцем. Авторизация Firebase CLI и вход на сайте — отдельные сессии.
