# Libre Ledger

Личный учёт товаров, закупок и продаж. React + TypeScript + Vite, GitHub Pages и Firebase Authentication / Firestore. Новое пространство пустое: товары и операции добавляет владелец.

## Работа с данными

- **Склад → Модели**: добавить, переименовать, поменять цвет или удалить модель. Удаление модели со всеми её операциями требует подтверждения и показывает число связанных записей.
- **Операции → Изменить**: исправить дату, товар, количество, цену, доставку и комментарий; отменить, восстановить или окончательно удалить запись. Отмена сохраняет историю и исключает запись из расчётов.
- Продажи списывают товар по средней закупочной стоимости с доставкой. Исправления пересчитывают учёт и проверяют остаток на каждую дату, включая последующие продажи. Закупки одного дня учитываются перед продажами этого дня.
- **Настройки**: состояние синхронизации, экспорт и проверяемый импорт JSON, полная очистка моделей и всех операций. Импорт заменяет пространство целиком. Файлы прежнего формата также поддерживаются.

Локальный учёт и учёт аккаунта разделены. Вход не переносит записи из гостевого режима: для намеренного переноса используйте экспорт и импорт. Кэш аккаунта и очередь несохранённых действий остаются в браузере после выхода, чтобы не потерять изменения; используйте доверенное устройство. Экспорт содержит ваши данные без шифрования.

## Синхронизация и ограничения

Изменения сначала сохраняются локально, затем отправляются транзакциями Firestore. Очередь переживает перезагрузку и повторную отправку. Независимые правки объединяются; конфликт одной записи требует выбора пользователя, а локальную копию можно скачать. После очистки меняется поколение пространства: прежние действия с другого устройства не могут вернуть удалённые записи. Получение снимка само по себе не создаёт запись в облаке.

Один документ поддерживает до **100 моделей, 3000 операций и 750 КБ** полезных данных. Цена / доставка — до 100 млн ₽ с точностью до копейки; совокупные суммы закупок и продаж — до 1 трлн ₽ каждая. Перед архивированием и очисткой сохраните JSON. Это личный товарный учёт, без многопользовательского редактирования прав и серверного журнала аудита.

GitHub Pages и проект Firebase Spark работают без платной подписки в пределах [квот провайдеров](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans). Cloud Functions, платные API и автоматическое подключение биллинга не используются. При исчерпании квоты синхронизация ждёт, изменения остаются на устройстве. При недоступном локальном хранилище новые изменения блокируются с объяснением.

## Разработка

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Node.js 22+. Публичная конфигурация существующего Web App находится в `src/firebaseConfig.ts`; для другого проекта используются `VITE_FIREBASE_*` из `.env.example`. Никогда не добавляйте в клиент сервисные ключи, OAuth-токены или пароль. Firebase Web API key идентифицирует приложение; доступ к данным защищают серверные правила.

В Firebase должны быть включены Email/Password, подтверждение почты, Firestore и домен GitHub Pages в Authorized domains. Текущие правила разрешают доступ только подтверждённому владельцу `andrewokop@gmail.com` к собственному `users/{uid}/workspace/main`. Для другого владельца нужно согласованно изменить правила и `allowedEmail`.

## Проверки и публикация

`npm test` проверяет расчёты, редактирование, импорт, очередь, конфликты и восстановление. Проверки правил требуют Java 21+ и эмулятора; без него эта группа явно пропускается:

```sh
npx --yes firebase-tools@15.34.1 emulators:exec --only firestore --project demo-libre-audit "npx vitest run tests/firestore.rules.test.ts"
```

Проверки используют изолированный demo-проект и не обращаются к рабочим данным. GitHub Actions запускает обе группы перед сборкой и публикацией Pages.

Сценарии реального браузера используют отдельную сессию Playwright CLI и только локальный сервер. Они очищают гостевой тестовый учёт. Создайте каталог `output/playwright`, запустите preview на 4173, затем:

```sh
npx --yes --package @playwright/cli playwright-cli -s=ledger-check open http://127.0.0.1:4173/
npx --yes --package @playwright/cli playwright-cli -s=ledger-check run-code --filename tests/management.browser.js
npx --yes --package @playwright/cli playwright-cli -s=ledger-check run-code --filename tests/readability.browser.js
```

Первый сценарий проверяет CRUD, отмену, восстановление, резервную копию и отсутствие предустановленных данных после очистки. Второй проверяет ширины 320–1440 px, крупные суммы, длинные названия и комментарии, контраст текста 7:1, шрифт от 14 px и кнопки от 44 px. Это автоматические проверки конкретных состояний, а не гарантия отсутствия любых ошибок.

Push в `main` публикует сайт через `.github/workflows/deploy.yml`. Правила Firestore публикуются отдельно из аккаунта владельца:

```sh
npx --yes firebase-tools@15.34.1 login
npx --yes firebase-tools@15.34.1 deploy --only firestore:rules --project freestyle-libr
```

При обновлении со старого формата выполняется согласованная очистка прежнего seeded-каталога: удаляется кэш `libre-ledger-v1*`, а облачный документ прежнего формата заменяется пустым пространством версии 2. Последующие входы и обновления версии 2 данные не очищают. Старые клиенты после публикации правил не смогут записать прежний формат.
